# 参考拆解：三个"agent 做视频"项目 —— 分别对 anim 有什么可取之处

> 拆解日期 **2026-10-10**。对象是三个成熟的开源项目，**都不是我们的竞品**（它们的定位与 anim 不同），
> 但每一个都有一层我们确实缺的东西。三份逐文件证据报告在旁边：
> [`REFERENCE-video-use.md`](REFERENCE-video-use.md) ·
> [`REFERENCE-hyperframes.md`](REFERENCE-hyperframes.md) ·
> [`REFERENCE-hypit.md`](REFERENCE-hypit.md)。
>
> ⚠ **待办不在这份文件里。** 本文只回答"别人怎么做、我们缺什么、值不值得搬"；
> **做完没做完一律以 [`BACKLOG.md`](BACKLOG.md) 为准**（本轮落成 **§1.B**，共 15 条）。
> 路线图那一层（"从必须写代码到只写配置"）在 [`ROADMAP.md`](ROADMAP.md)，两份不重叠。

## 0. 一句话结论

| 项目 | 它是什么 | **对 anim 最值得抄的一件事** |
|---|---|---|
| [video-use](https://github.com/browser-use/video-use) | 不是编辑器，是 26KB 的 `SKILL.md` + 6 个 ffmpeg 脚本；"LLM 从不看视频，它**读**视频" | **给 `anim sheet` 叠一条音频通道**（波形 + 静音带 + 旁白词标签）—— 一张 PNG 就能判定"画面揭晓时刻对不对得上旁白" |
| [hyperframes](https://github.com/heygen-com/hyperframes) | HTML 原生视频的组合契约 + 21 个 agent 技能 + 约 86 条 lint 规则；无头 Chrome 逐帧 seek 渲 MP4 | **把 `check` 从"像素体检"升级成"带断言的画面语义门"**（`motion.json`：该在几秒前出现 / A 早于 B / 不许静止超 2s / 帧边缘不许有硬内容） |
| [hypit](https://github.com/hypit-ai/hypit) | SVML 标记语言 + 组件包生态 + 多进程并发渲染；核心是**词锚定**的时间模型 | **把 `anim say` 的旁白时间线从"秒"改成"命名词锚点"** —— 作者写"说到『兽语』时切镜头"，求解器算出 `timing.mjs` |

三件事凑巧指向同一个方向：**我们已经有数据，缺的是"把数据变成判断"的那一层。**
（`sheet` 已经有抽帧、`narration.json` 已经有词级时间戳、`check` 已经有三点采样和逐段试渲染 —— 缺的都是最后一步。）

## 1. 三个项目的基本盘（可核实的差异）

| | video-use | hyperframes | hypit |
|---|---|---|---|
| 许可证 | MIT | Apache-2.0 | Apache-2.0 **+ 三条附加条件** |
| 语言 / 规模 | Python，6 个脚本 + `SKILL.md` | TS monorepo（core/engine/producer/studio/player/lambda） | TS monorepo（pnpm workspace + 组件包） |
| 渲染方式 | ffmpeg 拼已有素材（**无浏览器**） | 无头 Chrome CDP `beginFrame` 逐帧 seek + ffmpeg | 无头 Chrome，**多进程**（`applyFrame(绝对帧号)`） |
| 中间表示 | `edl.json`（取材清单：源 + `[start,end)` + grade + overlays + srt） | HTML + `data-*` 属性（`data-start` / `data-duration` / `data-track-index`） | **SVML**（标记语言）+ `semantic:Projection` 求解成绝对帧 |
| 时间模型 | 秒 / ffmpeg 时间戳 | 秒（编译期锁定的根时长 + 可重读的 clip 时长） | **词锚定**：词边界锚点 → 媒体本地对齐 → 绝对帧；**源里没有任何秒** |
| 确定性 | 弱（同 EDL 同输出，但**无任何逐像素验证**） | 中（seek-safe 硬契约 + 86 条 lint；作者自承"lint 干净仍可能出片坏掉"） | 中（编译器产出的帧函数是纯的；但依赖对齐/生成这类外部结果） |
| 素材 | 用户给的实拍素材 / `yt-dlp` | 用户素材 + HeyGen 媒资目录（可选） | 生成模型（**可选**）+ 用户素材 |
| 对我们的价值 | **音频量具与验证图** | **规则化的自检 + 可复用单元** | **词锚定时间 DSL** |
| 明确不要抄 | Python/numpy 生态、逐段重编码、云 API 强依赖 | HTML/CSS 表现力上限、GSAP 生态、DOM 副本式运动模糊、云渲染 | 生成模型优先、多租户渲染服务的那套工程细节、逐词高亮字幕 |

> 三份报告的"不适用/别照抄"清单（合计 20 条）比"可取之处"更长 —— **这是好事**：
> 一个参考项目如果有八成能抄，说明我们和它做的是同一件事。

## 2. video-use：可取之处

它的世界观是"素材既定，编辑是在已有语音里挑"—— 与 anim（画面是代码算的、旁白由 TTS 生成）**方向相反**，
所以能抄的很少、但抄的那两条极便宜。

### 2.1 ★ 给 `sheet` 叠音频通道（本轮性价比最高的一条）
它有一条命令出一张 PNG：**胶片带 + 波形 + ≥400ms 静音带 + 词标签 + 时间标尺**，横轴同一个时间窗，
并且明确写着"只在决策点调用，不要拿它当扫描工具"。我们三样东西都有（`sheet` 的抽帧、`narration.json` 的词级时间戳、
`src/core/audio-analysis.js` 的纯 JS 包络），**只是从来没叠在同一张图上**。现在"这句旁白说出口时画面揭晓到哪一步"
靠 `narration.mjs` 的 `cue` 盲写、出片后人眼比对。

### 2.2 响度数字守门
它两遍 `loudnorm` 打 `-14 LUFS / -1 dBTP / LRA 11`（对齐 YouTube/TikTok 等平台的归一化目标），
并把纪律写进自评："**你听不见，就说出这一点并报数字。**"我们的 `check` 用亮度数字、`shake` 用逐帧变化量、
`verify` 逐像素、`video` 复核帧数 —— **唯独音频这一层还在靠耳朵**。`scripts/lib/media.mjs` 加一个函数即可。

### 2.3 三条流程纪律（零代码）
- **切点两侧 ±1.5s 固定出图**（`check` 现在的三个采样点是 15%/50%/85%，**不落在切点上**）→ 一条 `anim cuts` 命令；
- **自检最多 3 轮**，3 轮不过就交人，不许无限循环；
- **审查者 brief 要"roast, not to praise"**：`docs/SCENE-BRIEF-TEMPLATE.md` 是*生产* brief，缺一份*审查* brief。

### 2.4 它踩过、而我们迟早会踩的坑（一旦要做素材裁切）
它用 12 条硬规则换来的经验里，有 5 条是"把预烘焙视频段拼进成片"必撞的：字幕必须在滤镜链**最后**、
逐段抽帧后无损 `-c copy` 拼接（否则每段双编码）、每个接缝补 30ms 音频淡入淡出（否则每次切都有爆音）、
overlay 要用 `setpts=PTS-STARTPTS+T/TB` 落位、母版 SRT 要按输出时间轴偏移。
**好消息：我们现在的"无接缝、一次编码、字幕在后处理之后"是结构性优势，不是欠账** —— 真做素材裁切时不能把这三条弄丢。

### 2.5 一条纪律 + 一条反面教材
- 它的 EDL 里每个剪辑决定都自带 `quote`（取了哪句原话）与 `reason`（为什么取它）。我们的配置档节点有 `note` 键，
  但没规定要写"为什么选这个镜头"。
- **它的文档与代码已经漂移**：`SKILL.md` 说字幕 `MarginV=35`，`render.py` 里其实是 90（"这是平台安全区，不是审美"）。
  照文档抄会踩坑。提醒我们：AGENTS.md 里那些散落常量（默认 4 秒、`maxSamples` 档位、字幕带 y 40–104）需要防线。

### 2.6 不要抄
Python/numpy 生态（它的注释自己写着"避免把 librosa 当硬依赖"——**能用纯 JS 做到的不值得引数学库**）、
逐段重编码 + concat 的管线（会把自己从"一次编码、任意 seek"降级）、云转写 API（我们的 `edge_tts` + 离线假驱动更好）、
"LLM 从不看视频"当教条（我们该优化的是"少看几次"，不是"不看"）、2 词大写字幕风格（与我们的字幕纪律冲突）。

## 3. hyperframes：可取之处

它的赌注是"HTML 能直接播"（作者的广度），代价是**把确定性从语言层面下移到了工具层面** ——
于是它被迫长出约 86 条 lint 规则来堵 seek 顺序类的漏洞。**这恰好是我们最该借的一层：规则化的自检。**

### 3.1 ★ 画面语义层的断言（本轮第二高价值）
它的 `check` 不是"量亮度"，而是可枚举、可 gate、带修复提示的规则。其中 anim **完全没有**、且真能防住
"不报错但画面错"的：

| 它的规则 | 防的是什么 | anim 的对应现状 |
|---|---|---|
| `sweep_static` / `motion_frozen` | **一段画面根本没动**（3s+ 无可见变化直接 fail；某窗口静止超 2s 报错） | `check` 只量亮度 —— "画了但没动"照样通过 |
| `motion_appears_late` / `motion_out_of_order` | 该出现的没出现、A 该早于 B 却反了 | 完全没有 |
| `canvas_content_at_edge` | 帧边缘出现硬内容（元素出画、文字被切） | 完全没有，**而 anim 全是 canvas** |
| 对比度审计 | WCAG AA + **给出同色系里最近的合规颜色** | 风格包定义了调色板，但没人校验实测对比度 |
| `gsap_fullscreen_overlay_starts_visible` | 铺了一个盖住一切的东西 | 我们的背景守门只查"没铺 = 纯黑" |
| `gsap_non_transform_motion` | 慢速运动被量化到整数像素 → 一顿一顿 | 场景里 `Math.floor(x)` 同样会顿，没人拦 |

两条**元设计**比规则本身更值：
- **"严重性是持久性感知的"**：只在单个采样点出现的动态问题降级为 info、永不 gate；**跨采样点保持**才 gate。
  `check` 已经是三点采样（15%/50%/85%），**基础设施已经有了**，只差把"三点是否一致"从亮度扩展到别的量。
- **"空 ≠ 干净"**：它的 `check --json` 里有 `browserSkipped` —— 浏览器没跑起来时，布局/运动/对比度三个 section
  是**空的，不是干净的**。这正是我们 `check` 现在最大的语义漏洞：某段试渲染失败，如果只是少打一行，
  agent 会当成通过。

### 3.2 可复用单元与注册表
它把单元分成两级 —— **Block**（独立子合成：有自己的尺寸/时长/timeline）与 **Component**（效果片段：无尺寸无时长，
直接粘进宿主）—— 每项带 `registry-item.json`（name / title / description / tags / files），
用 `catalog --query` 发现、`add` 安装，搜索**完全本地、不发 query**。
我们 `src/shots/` 的 8 个模板**硬编码、只有"查参数"没有"装新的"**，`kit` 里的 `panel`/`kicker`/`codeRow`
是天然的"效果片段"却只能在场景代码里 `import`。它的元数据契约足够薄，可以直接照抄成
`shot.meta.json` + 两级 `kind: 'shot' | 'effect'`；**但别抄它的远端清单**（离线能搜不能装），
我们的版本应该是"本地目录 + 生成的索引"。

### 3.3 design system → 视频的翻译层：**"数字来自脚本"**
它的口号是 "Atoms stay sacred. Composition stays free. **Numbers come from the script.**"，
第三句落成了硬规则：**"绝不在帧尺度上编造数字、增量、日期或计数；槽位先渲染成 `— figure —`"**，
并配一条交付前自审（"每个数字都能追溯回脚本，否则是占位符"）。
这条对 anim 尤其重要 —— **我们的画面全是代码算的，编一个数字的成本是零**。
我们已经有 `FACTS.md` / `FACTS-TEMPLATE.md`（对外材料逐句标出处），缺的是把这条约束**伸到画面上**。

另外两件小的：它的 style token 分 **normative（引用必须逐字、不许四舍五入）vs context（读它做判断）** 两层；
它的 `frame.md` 每个 treatment 都有 **Fixed / Free 两栏**（什么不可动、什么按内容变）——
我们现在的风格包是"整包换"，缺这个中间粒度。

### 3.4 运动的原子规则（可以直接变成 kit 函数的默认值）
它有 7 大类 40+ 条原子规则，每条是"一句内涵 + Tags"、共享契约只写一次。其中**具体数字可以免费拿走**：
- `nudge-curve`：三段式整组位移，**距离分配 10/65/25，尾部时长 ≥ 3× 加速段**；
- `reactive-displacement`：**受害者的时长是入侵者的 40–50%**；
- `waterfall-entry`：**"到达不要用淡入，要用二值出现"**；`items × stagger ≤ ~0.5s`；
- 各类上限（辉光峰值 opacity ≤ ~0.45、粒子 ≤ ~40 个）—— **"上限"是把抽象品味变成可检查的桥**，
  而我们的文档里几乎全是"不许"，很少有"最多/最少"。
还有一条写法上的启发：它的 `theme-crossfade-morph` 是"**堆叠完整图层 + 只做 opacity 交叉淡入**"——
对"整主题形变"这类镜头，比参数插值更容易保证两端都对。

### 3.5 面向 agent 的文档工程
六个可照抄的部件：**开篇先给坑（带规则名）→ 能力地图（"读它是为了…"）→ 契约 → "第一次构建必踩"清单 → 校验清单**；
技能 frontmatter 的 `description` 里写 **`Don't use for …`**（这是给路由器看的）；
**诊断输出里的词与"怎么修"用同一份词表**（否则 agent 拿到 `flat` 不知道该干嘛）；
以及一条我们做得很好的、要保持的：**每条禁令挂一个历史事故**（"fidus 那次 9 段里 8 段这样"）。

### 3.6 不要抄
HTML+CSS 的表现力上限（它禁 tween `width/height`、禁动 `letterSpacing`，因为浏览器布局会整数吸附 ——
**我们没有布局，所有坐标是自己算的**，该抄的是"慢速运动别量化"的意图而不是字面）、GSAP/React 生态绑定、
它的 DOM 副本式运动模糊（**我们是逐子帧物理积分，别倒过来学**）、"允许有状态"的确定性模型、
DOM 盒子式的布局审计（我们的画面没有盒子）、13 个 frame preset 的内容、云渲染/Lambda（我们的瓶颈在 GPU 填充率，
搬上 CPU 云只会更慢）。

## 4. hypit：可取之处

### 4.1 ★ 词锚定：把 "cue: 0.6" 这类猜秒数彻底消灭
它整个语言里**没有任何秒**：作者写 `@{hair-gel} … @{/hair-gel}`（命名语义区间）与 `@{trophy!}`（命名语义点），
`~` 用来消歧"两个词之间那段停顿归谁"（左亲和/右亲和/都不吃）。求解严格分三段：
**Script（纯符号锚点，零时间）→ WhisperX 对齐（锚点在"媒体本地域"的帧号）→ Projection（映射成绝对帧/窗口）**。
消费者（B-roll、字幕、揭示板）只写 `during={selection-hair-gel}` —— **"这张图在'发胶'那个词的区间里出现"**，
至于那是第 143–187 帧，是求解器算的。所以改名后重跑，一切自动跟到新时间：
**"timing re-flows itself" 不是因为有个聪明的重排算法，而是因为时间从来就没被写下来过。**

**我们已经有全部前置条件**：`anim say` 已经产出词级时间戳（`narration.json` 的 `lines[].words`，整片绝对时间），
`type.karaoke` 已经在用。缺的只是**语法的表达力**与那个纯函数求解器。
建议做法（四条）：给 `narration.mjs` 加"命名词锚点"（抄语义**不抄** XML 标记，因为我们的输入已经是结构化 JSON）；
写 `resolveNarration()` 输出**现有的 `timing.mjs`**（场景侧一行都不用改）；
**必须实现左右亲和**（否则词间停顿被静默归错，且不报错）；
求解顺序是**锚点 → 段内时刻 → 再算 `stretch`/`slot`**（两者正交，但段内偏移要跟着乘 `stretch`）。
风险与边界：中文分词可能与作者心里的"词"不一致（**匹配不到就抛错并列出该句所有可用词**，与我们的报错哲学一致）、
每段限制 2–3 个锚点（**锚点太多就变成另一种秒数**）、
**锚点只表达"在哪个词上做什么"，永远不能表达"持续 3 秒"**（否则 `stretch` 求解失去唯一解）、
无词级时间戳时要能降级回秒并**在 `check` 里警告"这一段改词不会自动重排"**。

⚠ **不要照抄它的"等长、不许拉伸"**：它的投影拒绝 clip/stretch/resample，而 `solveTiming` 的核心恰恰是 `stretch`
（`MAX_STRETCH = 1.9`）。**两套时间哲学：它让画面去适配词，我们让旁白去适配画面。**

### 4.2 组件包机制：先写契约，别急着做生态
它的组件有八个职责角色、**双版本号**（源码里写逻辑接口版本 `@1`，npm 决定物理实现）、
默认住在视频项目自己的 `packages/` 下，要分享就 `npm pack` 或发自己的 scope ——
**"用这个组件完全不需要 checkout 上游仓库"**。官方 Distribution 与社区共享是**两条独立通道**：
工程门槛极低，生态门槛是产品判断（进官方要先开 issue 说清"共享的产品需求"）。
对我们的建议是**只做最小版本**：给每个 shot 补一份**声明的 spec**（参数类型/默认值/`requires` 依赖/是否自己铺满整帧），
让 `check` 能提前报出"这一段是 `wave` 但任务没配 `audio`"。**调用签名一个字不用改。**
真做成 npm 分发是一次架构手术，而我们是单仓、8 个模板、一个作者 —— 等真出现"给第二支片子复用"的需求时，
有了 spec 再抽包就是机械工作。

### 4.3 并发渲染：前提我们已经有了，但**先量再抄**
它的地基是一句：编译产物暴露 `applyFrame(绝对帧号)` 且"**不要求顺序播放**"（渲染器不是播放器），
于是帧区间切块、一个 worker 一块、可以从任意帧开工；乱序捕获由 `OrderedFrameSink` 按字节预算缓冲、顺序喂给唯一的 ffmpeg。
**我们的铁律第一条（每帧是 t 的纯函数）正好等价于它的"任意帧可开工"。**
但真实的取舍在这里：我们的 `--parallel N` 已经做了"多进程各自私有 Vite + 各自 Chrome + `-copyts` 拼接"，
**而 NV12 之后实测 4 进程 720 帧 6.1 fps < 单进程 7.5 fps** —— 瓶颈在传输与核显争用，不在 CPU 并行度。
所以：**它的 `distributeFrameRange`（十行）可以抄，它的调度器不要抄**。
顺手该修的是现有 `--parallel` 的两个已知毛病（会静默忽略 `--segments`、只转发 10 个参数）与
"并行度上限 8 / 不默认开 / 按 `min(cpu-2, 内存/3GiB)` 起算"（它的 `byMemory = mem/2/1.5GiB` 是可直接用的经验值）。
**值不值得做，取决于先量一次**：单机同时起两个 `--segments` 渲不同段，看总墙钟是否真接近减半。

### 4.4 变体 / 批量
`variants` 覆写（深合并 + 按 variant 分目录）+ **让 `narration.json` 成为可显式指定的输入** ——
后者的价值更大：改一句词现在会导致整片重渲，而"这一段用上次那份词级时间戳、不要重新合成"
就能让换风格/换配色/换顺序的变体零 TTS 成本重出。

### 4.5 一条半小时的小事
它的 Studio 把评论做成**普通项目文件** `FEEDBACK.json`（`{id, run, at, text, resolved}`，`at` 是秒），
读写都走文件、不轮询不重编译。我们可以在 `out/<任务>/` 放一个同构的 `NOTES.json`，
让"第 12.5 秒这里字幕太小"这类反馈有个落点。

### 4.6 不要抄
把 anim 往"生成素材"方向拉的任何机制（提示词/图片生成/视频生成/音色设计 —— 引入一个就会有人往里塞提示词，
`check` 的确定性保证就废了）、它的 caption 体系（逐词高亮、人脸检测驱动字幕位置 —— 与
`docs/CAPTIONS.md` 的实验结论**正面冲突**）、Studio 的 GUI 反向求解器（我们的作者读代码，改时间就是改代码）、
多租户渲染服务的那套工程细节（有序汇的字节预算、加权租约、爬坡退让 —— 那是**服务**的必需品，不是**引擎**的）、
`||` 字幕换气符（我们的字幕由引擎层按 ≤16 字/行自动生成，作者不该手控换行）。
许可证上：**抄机制不抄代码**；它的"多租户禁令 + 商业再分发禁令 + LOGO 不可去除"三条与我们的 MIT 不兼容，
一旦对外提供服务就不能带它的代码或衍生代码。

## 5. 交叉验证：三个项目独立指向的同一件事

这三份报告是**互不知情**地做的（三个并行子代理，各自只看到自己那个仓库），但有三处结论撞在一起 ——
撞车的地方可信度最高：

1. **"验证要变成一张图/一条断言，而不是若干张待解读的图"**
   - video-use：胶片带 + 波形 + 静音带 + 词标签合成一张 PNG（**决策点**调用，明确反对扫描式翻图）；
   - hyperframes：把"该在 X 秒前出现 / A 早于 B / 不许静止"写成可 gate 的断言，让机器替你看；
   - hypit：把"画面该在哪个词上做什么"写成引用，机器每次重解。
   → 我们的 `check` / `sheet` / `still` 已经是"看图验证"，缺的是**把判断也放进去**。

2. **"作者不该猜秒数"**
   - hypit 最彻底（语言里没有秒）；hyperframes 的根时长编译期锁定、clip 时长由变量驱动；
   - video-use 用词级时间戳给剪辑点。
   → 我们的 `narration.mjs` 里 `cue: 0.6` / `internal: 4.2` 正是"靠猜"，而 `words` 已经在手上了。

3. **"空的结果不能算通过"**
   - hyperframes 明写 `browserSkipped` 时三个 section 是**空的、不是干净的**；
   - video-use 的"资源缺失必须硬报错，绝不静默渲染一个没字幕的片子"；
   - hypit 的"投影长度不匹配就是错误，不裁剪不拉伸不隐藏"。
   → 我们的 `check` 在"某段试渲染失败"时会不会静默通过？`--parallel` 会不会静默忽略 `--segments`？
   这类"静默降级"是我们最贵的 bug 类型。

## 6. 建议顺序（详细条目与验收见 [`BACKLOG.md`](BACKLOG.md) §1.B）

| 顺序 | 做什么 | 为什么排这儿 | 代价 |
|---|---|---|---|
| 1 | **给 `sheet` 叠音频通道**（词标签 + 波形 + 静音带） | 数据全在手上，一张图省掉"数时间"，**改了立刻每天都用得上** | 小（一个工具脚本，不碰 GPU） |
| 2 | **词锚点 → `timing.mjs` 求解器** | 唯一"把已有能力兑现"的一条，直接消灭猜秒数 | 中（1–2 天，纯逻辑可离线回归） |
| 3 | **`check` 加画面语义断言**（动没动/顺序/帧边缘）+ **"空≠干净"** | 防的是我们文档自己承认的最贵失败；复用现成三点采样 | 中（先做最小三条，可一条条加） |
| 4 | **响度数字守门**（`-14 LUFS / -1 dBTP`） | 最后一层还靠耳朵的验证 | 小（一个函数） |
| 5 | **`shot` spec + 依赖前置校验** | 让"没配 audio 就用 wave"这类错误提前炸，而不是渲染成黑屏 | 小 |
| 6 | **`--parallel` 修毛病 + 并发度上限 + 真量一次收益** | 已知两个 bug + 一个未验证的旧结论 | 小（先说清事实，再决定要不要动） |
| 7 | 变体（`variants` + `narration.json` 可指定） | 同一支片出多版本的需求会来 | 中（1 天） |
| 8 | 运动规则表（`docs/MOTION.md`）+ 3 个 kit 函数 | 只改善"选择质量"，不改引擎能力 | 小（写文档为主） |
| 9 | "数字来自脚本"写进 FACTS 纪律 + 交付自检 | 伤害面最大、成本最低 | 小（先文档后自动化） |
| 10 | `anim cuts`（切点两侧 ±1.5s 出图）+ 审查者 brief + 3 轮上限 | 把"每一段都看过"从纪律变成命令 | 小 |

**排最后的**：镜头包注册表（先把 spec 写对）、分布式/云渲染（我们的瓶颈不在那儿）、
GUI 反向求解器（解决一个不存在的问题）、任何引入生成模型的机制（会毁掉确定性保证）。
