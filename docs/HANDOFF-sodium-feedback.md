## 0. 一分钟版本

2026-10 发布的**钠那期视频**（`tasks/sodium`，246s / 13 段）收到的评论集中在三件事：
看不懂、元素互相遮挡不知道看哪个、建议改做 PPT 或网页。

我们把这三条**逐条对到了产物上，全部成立**，而且**都是「信息设计」层的问题，不是引擎问题**：

| 批评 | 病因（可查） |
|---|---|
| 「不如纯看字幕了 / 不明所以」 | **43 句旁白里 12 句（28%）被逐字抄到了画面上** ⇒ 眼睛读到和耳朵听到的是同一句话，画面没有额外信息 |
| 「元素相互遮挡，不知道要看哪个主体」 | **一屏 4–6 个信息块**（眉标 + 右上读数面板 + 左侧标签列 + 图示 + 说明条 + 出处脚注）；单场景文字调用最多 14 处 |
| 「观感很差 / 推荐做成 PPT」 | 交付时**画面上有逐字说明条、又另烧了一遍 `.ass` 字幕**（引擎字幕层没开）⇒ 观众说的「两条字幕」；12 分钟线性播放也没有节奏控制权 |

**结论：不要返工 sodium**（用户的既有原则：已交付的当教训，不当返工对象；且他明确说过不用再管）。
要做的是**把这三条变成下一支片子的纪律与判据** —— 这是这个项目最擅长的那件事：
把「不报错但观众看不懂」变成 `check` 能报出来的东西。

## 2. 诊断（三条，每条都能复现）

### 2.1 画面在复述旁白 —— 28% 的句子被逐字写进画面

复现：

```sh
node tools/lint-narration-dup.mjs sodium
```

实测输出（2026-10-16）：`合计：1 个任务 / 43 句旁白，12 句被逐字写进画面（28%）`，另有 3 处「部分复述」。
命中的具体位置（`文件:行号`，可直接打开看）：

- `tasks/sodium/scenes/cull.js:288` / `:289` / `:290`（第 5 段 cull 的三条说明条）
- `tasks/sodium/scenes/bfs.js:300`、`tasks/sodium/scenes/threads.js:234`、`tasks/sodium/scenes/glass.js:307`
- 其余见工具输出（它会逐条打印「命中」+ 源码）

病因：`docs/CAPTIONS.md` 的纪律 1「**画面文字只放标注**（名词 / 数字 / 单位 / 出处），句子交给旁白与字幕」
在这支片子上**没有执行**。而且这件事**早就记过账**：`docs/BACKLOG.md` 的 **0-2** 写着「sodium 12/43 句复述，
清了就能让 lint 归零；**不做也可以**：它们已交付，复述是观感打折不是错误」。
→ 现在有外部反馈了，这条待办的**定价该重估**（但方向是"下一支别犯"，不是"返工这一支"）。

### 2.2 一屏的元素太多、没有主次

复现（从**已有成片**抽 12 帧拼成联系表，不重新渲染）：

```sh
ffmpeg -y -v error -i out/sodium/sodium.mp4 -vf "select='not(mod(n,1230))',scale=640:-1,tile=4x3" -frames:v 1 out/_staging/sodium-contact.png
```

看那张图：典型一屏 = **左上眉标 + 右上读数面板（一屏 4–6 个数）+ 左侧标签列 + 中间的图示主体 + 下方说明条 + 出处脚注**。
各场景的「文字入口调用数」粗略统计（`grep -cE "type\.(write|writeLine|karaoke)|caption\(|panel\(|kicker\(|footer\("`）：

```
glass.js: 14   _world.js: 9   dispatch.js: 9   world.js: 7   compact.js: 6
batch.js: 5    bfs.js: 5      threads.js: 5    vram.js: 5    outro.js: 5
cull.js: 4     hook.js: 4     enter.js: 2
```

引擎侧**目前没有任何判据**管这件事：`check` 管的是亮度 / 背景守门 / 非有限值 / 依赖令牌；
`src/kit/bands.js` 只有「版面分区（六条带 + 字幕保留带）」，**没有「元素数量上限」与「主体是谁」**。
这是这三条批评里**最值得工程化**的一条。

### 2.3 两层字幕（画面说明条 + 另烧的 .ass）

- `tasks/sodium/task.config.mjs` 里**只有** `narration: './narration.json'`，**没有** `captions: true`
  ⇒ 引擎字幕层没开（引擎的字幕层见 `docs/CAPTIONS.md` / `src/core/captions.js`）。
- 交付版本是**另外烧的字幕**：`out/sodium/sodium.ass` / `out/sodium/sodium.srt` / `out/sodium/sodium-subbed.mp4`。
- 于是观众同时看到：引擎画的 12 条**逐字说明条** + 烧上去的**字幕** —— 字面上的「两条字幕」，
  正是 `docs/CAPTIONS.md` 开头引用的那句观众反馈「两条字幕同时出现，看着好迷糊」。

## 3. 这说明了什么（判断，写清楚依据）

1. **引擎侧没问题。** 同一轮的证据：整份 `regress-all`（49 项）**48 通过 + 1 跳过（环境）+ 0 真失败**；
   成片 `verify` 通过、4K / TTS / 分块 / 运动模糊都在跑。**失败发生在「编辑部」那一层**：
   每屏放几件事、画面说什么、节奏给谁控制。
2. **「编辑部」恰好是最便宜的修改**（不用碰 `src/**`）。反过来说：把引擎再做深，**不会**让下一支片子好看。
3. **不返工 sodium**（见 §0 的结论）。它现在的价值是**夹具与证据**：
   把它当反面样本去标定判据 —— `"判据能不能把这三条抓出来"` 就是一个可验证的验收。
4. 关于「做成 PPT / 网页」：观众真正要的是**节奏控制权**（高信息密度 + 线性播放 = 读不完也没法停）。
   技术上我们**具备条件**（每帧是时间的纯函数 ⇒ 可以出可拖时间轴 / 逐帧揭晓的页面），
   但**先不要一头扎进去**：先做 §4 的第 3 条（最小样张）看值不值。
5. 5 条评论 ≠ 项目判决。但**不要只挑好听的信** —— 这三条方向一致、能对上产物，就该改设计。

## 4. 三条候选行动（等用户拍板；可以只做一条）

### 方案 1：把这三条批评变成检查项（推荐，最符合这个项目的强项）

**做什么**：在 `anim check` 里新增一段「版面守门」，至少覆盖：

- (a) **每屏文字区数量上限**：引擎侧给每段记「这一帧调了多少次文字入口 / 画了几个面板」
  （`Layer2D` / TextLayer 上各加一个计数器即可，与已有的 `gl.paint` 记账同一个套路 —— 见 `src/core/gl.js` 的 `paint` 与 `src/app.js` 的 `worldAudit()`）。
  超过阈值（建议先定 **主体之外 ≤2 个**）就报 `文件:段名`。
- (b) **主体声明**：场景可选 `export const focus = { x, y, w, h }`（或 `focus: 'center'`）声明「这一段看哪里」；
  kit 的 `assertInBand()` 已有同类机制（`src/kit/bands.js`），照它的形状扩展成 `assertFocus()`：
  非主体元素进主体区 / 亮度超过主体 ⇒ 警告进 `ctx.warnings`，`check` 汇总打印。
- (c) **复述率变成 gate**：`lint-narration-dup` 现在已经能报 `文件:行号`，把它从「建议」接进 `check`
  （参照 `check` 里 `lint-narration-dup` 那段已有的调用，见 `scripts/anim.mjs` 里 `旁白复述检查` 的 `skipped` 分支）；
  默认 warn、`--strict` 下变 errs（与既有哲学一致：**默认不改退出码**）。

**产出物**：判据代码 + 离线单测（纯函数，照 `tools/test-timeline-audit.mjs` 的形状）+ `docs/LAYOUT.md`（排版纪律）。

**验收（关键）**：拿 **sodium 当夹具** —— 判据跑在 sodium 上必须**把这三条全部点名**；
同时 `hashes demo --baseline` / `hashes beat --baseline` 必须 **max 0**（判据不该动画面）。

**成本**：一轮（渲染验证几次，几分钟）。**风险**：阈值定太紧会把正常片子染红 —— 先只报不改退出码。

### 方案 2：出一支 60–90 秒的**单主题样片**

**做什么**：新任务目录（例如 `tasks/explain-60s`），纪律写死：
一屏**一个主体**、画面文字**只放标注**（名词 / 数字 / 出处）、读数**一次只揭一个**、
段长由旁白决定（`docs/NARRATION.md`）、开 `captions: true` 且**不再另烧字幕**。

**产出物**：一支成片 + 一份 `FACTS.md`（数字有出处）+ 一张 `sheet` 联系表。
**验收**：`check` 全绿；`lint-narration-dup` **零命中**；每段 `still` 抽帧用 Read 工具看过；
人眼判断标准就一句：**「一屏只让我看一件事」**。
**成本**：选题 + 写稿 + 渲染（一次几分钟）。**风险**：选题要用户定（不要自己编内容 —— 见 §5 的事实纪律）。

### 方案 3：回答「网页 / PPT」那条（最小样张，不是产品）

**做什么**：拿方案 2 的同一批素材，出一个**一页一图一解释**的静态页面（或者一支 12 帧的分节卡），
让用户对比「视频 vs 可停页面」哪种更适合他的内容。**只做样张，不做产品**。
**产出物**：一个 html（或一张长图）+ 一句结论「值 / 不值」。
**成本**：低（不用渲染新东西，用 `still` 出的帧就行）。**风险**：容易滑向「再做一套交付管线」，要克制。

## 5. 下一个会话必须知道的硬约束（这个仓库的坑，别踩）

1. **渲染期间一个文件都别写**（包括 `docs/*.md`、`tools/**` —— 编辑器的原子写会留下 `.tmp` 临时件，
   Vite 撞 `EBUSY` 直接崩，渲染报 `net::ERR_CONNECTION_REFUSED`）。**并发子代理的产出先落 `out/_staging/`**，
   渲染结束再搬进仓库。开渲之前先让所有子代理停手。
2. **Windows 上别用 PowerShell 写文件**（`Set-Content` / `Out-File` / `>` 都会毁掉 UTF-8 中文或加 BOM）：
   用编辑器式文件工具，或 Node 脚本 `fs.writeFileSync(p, text, 'utf8')`。
3. **改引擎 / 时间线 / 镜头模板之后**，必须跑 `node scripts/anim.mjs hashes demo --baseline` 与 `hashes beat --baseline`
   （两个任务各 11 帧，证明画面**逐像素没变**）。
4. **文案与数字必须有出处**：对外材料里的每句话、每个数字都要能在 `tasks/<任务>/FACTS.md` 找到来源，
   **宁可留空也不许编**；不清楚就问用户（他的原话：「不要瞎编，内容一定要有事实依据，不清楚的随时问」）。
   自查：`node tools/lint-fabricated-numbers.mjs <任务>`（注意：**它不覆盖「算出来的数字」**，那些会单列成「没验」）。
5. **交付前自检**（`AGENTS.md` §10）：`check` 无报错、逐段 `still` 出图并**真的看图**、有旁白就开 `captions`、
   风格相邻两支要换。
6. **文档地图**：`docs/BACKLOG.md` = 唯一待办清单；`docs/DIAGNOSIS.md` = 输出词 → 含义 → 修法；
   `AGENTS.md` = 操作契约（先读）；`docs/history/` = 归档（**不要当待办读**）。
7. 与用户交流**用中文**（回复与思考过程都是）。他偏好**并行子代理**，不喜欢串行硬等。
