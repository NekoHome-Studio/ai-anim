## 2. 技术性断言：逐条核实

### 2.1 「没有图片素材 / 没有视频素材 / 没有扩散模型」—— 真的吗？

**成立（指这支片子的素材来源）。** 素材全部是**运行时算出来的**：

| 核查项 | 结果 |
|---|---|
| 本任务的素材目录 | `tasks/promo/` 下只有 `scenes/*.js`、`fonts/*.woff2`、`audio/bed.{wav,mp3}`、`task.config.mjs`、`SCRIPT.md`、`FACTS.md` —— **没有一张图、没有一段视频** |
| `public/` 里有什么 | 只有 `fonts/fonts.css` 与 `fonts/Manrope-600.woff2` |
| 全仓库图片/视频文件 | 只有两类：`out/**` 的**渲染产物**、`out/_ref/pdoom-video/**` 的**只读参考克隆** |
| 场景会不会读图 | 逐文件搜 `tasks/promo/**`：**零命中**（没有 `new Image()`、没有 `.png'` 路径） |
| 扩散模型 | 仓库里没有任何模型文件、推理代码或对扩散模型的调用 |
| 字体 | 本任务**自带** 6 个 woff2（Inter / IBM Plex Mono / Noto Sans SC 子集，均 SIL OFL 1.1，来源写在 `tasks/promo/fonts/brand.css`）—— 字体不是"素材"，是排版资源，屏幕上的话不含此意 |

> 屏幕上可以说「没有图片素材」，因为：**最终画面里没有一帧来自图片文件。**
> 不要说成「引擎不支持图片素材」——引擎是支持的（`docs/COOKBOOK.md:853`）。

### 2.2 「每一个像素，都是算出来的」

**成立。** 三条渲染路径全部由代码在渲染时产生像素：

| 层 | 怎么出像素 | 出处 |
|---|---|---|
| 矢量 | `LineBatch`（GPU 胶囊线段，一次 draw call 画几万条矢量） | `README.md:115` |
| 全屏效果 / 3D | `Pass`（全屏 GLSL）；本片段 3/4/6 是 raymarch（每像素几十次 SDF） | `README.md:115`；`docs/ENGINE.md:333` |
| 文字 | `Layer2D` + `TextKit`（Canvas2D 文字，上传后由 `Compositor` 合成） | `docs/ENGINE.md:146` |

→ 正因为文字走 Canvas2D，屏幕上的措辞**没有**写「由着色器与几何」（那会把文字排除在外）。

### 2.3 「每一帧都是时间的纯函数」

**成立，而且就是引擎的头号契约**（`AGENTS.md:13`），但有三条明写的限制：

| 限制 | 原文 | 出处 |
|---|---|---|
| 有状态场景**直接抛错** | `声明了 stateful/integrates，无法做运动模糊采样。` | `src/core/engine.js:540`；`docs/ENGINE.md:83` |
| 严格说清「不依赖什么」 | `只依赖 t，不依赖上一帧、不依赖墙钟、不依赖随机` | `AGENTS.md:13` |
| 已知的唯一反例：成片**末帧**不是逐字节相同 | `末帧逐字节比 max 28 / mean 5.5 —— 边界的子帧取整差一点，肉眼看不出（>64 的像素 0.000%）` | `docs/STATUS.md:765` |

本片自己的机械验收：`node out/_probe/continuity.mjs`（六个切点上摄影机位置/朝向/滚转/速度连续、
母题逐帧位移 ≤ 0.043 世界单位、调色参数连续）；`node scripts/anim.mjs check promo` 通过。

### 2.4 「任意 seek / 真运动模糊」

| 断言 | 核实 | 出处 |
|---|---|---|
| 可以任意 seek | **成立**，且是引擎的验收标准 | `docs/ENGINE.md:81` |
| 真运动模糊（多子帧求平均） | **成立**：本片成片用 `--samples 8` | `docs/ENGINE.md:1065` |

### 2.5 「它自己读代码、渲染、看图、改」

| 支持它的原话 | 出处 |

| `这个项目是**为 AI agent 设计**的：\`AGENTS.md\` 是写给模型看的操作契约，它能自己读代码、渲染、看图、改，直到片子对为止。` | `README.md:5` |

## 6. 本片的验收记录

| 项 | 命令 | 结果 |
|---|---|---|
| 逐段体检 | `node scripts/anim.mjs check promo` | ✓ 没有问题（6 段 × 15%/50%/85% 三个点 × 单子帧/多子帧两条路径，共 36 帧；背景守门与非有限值扫描都过） |
| 一镜到底连续性 | `node out/_probe/continuity.mjs` | ✓ 五个边界：位置 Δ≤0.017 世界单位、朝向 Δ≤0.017、滚转 Δ≤6e-5、**切点两侧速度比 1.00–1.22**、调色 Δ≤0.016；母题逐帧最大位移 0.043；摄影机全程在世界腔体内（最小离墙 0.20） |
| 出片前自检 | `node out/_probe/preflight.mjs` | ✓ 语法（9 个文件）/ 禁止写法（`Math.random`、`Date.now`、`performance.now`）/ **抖动不是逐帧白噪声** / 连续性 |
| 成片 | `node scripts/anim.mjs video promo --segments 8 --samples 8 --idle 300` | **2880 帧 / 48.000s / 1920×1080@60 / h264 + aac 双声道**，9 块拼接，**ffprobe 复核通过**；1,228.3 MB；用时 2760s（46 分钟）。**这是修掉镜头抖动之后重出的一版**（前后对照见 `SCRIPT.md` §3.1、`docs/IMPROVEMENTS-3.md`） |
| 成片验收 | `node scripts/anim.mjs verify promo` | ✓ **14 个时刻（按帧号对齐）全部与重新渲染一致**：mean 1.69–8.8（判据 <18）。高值出现在高频画面（raymarch 排线 + 密线框）上，是 h264 的正常代价，不是渲染差异 |
| 镜头稳定性 | `node out/_probe/jitter.mjs out/promo/promo.mp4 46.5 8` | ✓ 成片逐帧整体位移 **±1px / RMS 0.27px**（修之前是 ±2–8px / RMS 3.64px、相邻帧之差最大 13px） |

> ⚠ 诚实记录一处：`verify` 里几帧的 `max` 到 166–255、`>16` 占 10–18%（t=16.02 / 36.02 / 39.00）。
> 这与 `docs/STATUS.md` §11.7 记的"高频细密画面"档一致（那里是 mean 7.0–7.7 / >16 13–17%），
> 而"拿错成片"那一档是 mean 26–43 —— 能分开的判据是 `mean`，不是 `>16`。
> 想更严可以 `--samples 1` 重渲（那条路上与成片逐字节相同，是最强的验收）。
