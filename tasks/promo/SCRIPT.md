# promo · 一镜到底宣传片 · 脚本与设计

> 48.0 秒 / 1920×1080 / 60fps / 120bpm（一拍 = 0.5s，全片 24 小节）
> **零 overlap、零 handlesTransition** —— 连续性靠「一个世界 + 一台摄影机 + 一个母题 + 一套调色」，
> 和 `tasks/pdoom-lab` 同一套手法（见 `docs/STATUS.md` §13.1）。
> 屏幕上每一句话的出处见 `FACTS.md`；机械验收见 `out/_probe/`（一镜到底的连续性探针）。

## 0. 一句话

**一台摄影机从一行代码里出发，穿过由代码算出来的世界，最后停在一块写着「写代码，就是做动画」的墙前。**
全片没有一次剪辑、没有一张图片素材 —— 这句话本身就是片子的内容。

## 1. 世界坐标（全片唯一）

右手系：`+x` 向右、`+y` 向上、`-z` 是前方（`src/core/cam.js` 的约定）。
**摄影机只沿 -z 前进**，六个"章节"就是这根轴上的六段 —— 换场景 = 走到了世界的另一段。

| z 区间 | 是什么 | 谁在画 |
|---|---|---|
| `0 … −22` | **代码走廊**：编辑器三维化（墙面代码条纹、地板刻度、每 8 行一道门、门楣上的真代码） | 投影线段批（`_world.js`） |
| `−21` | **门**：一道发光的长方框 —— 两个渲染世界都画它 | 线段 + SDF |
| `−22 … −46` | **大厅**：SDF 柱廊 + 每 5 个单位一道方环 + 顶部灯带 + 体积光尘 | raymarch（`_sdf.js`） |
| `−46 … −104` | **晶格隧道**：每 3.2 个单位一组方环（另一组转 45°），无限重复 | 同一份 SDF |
| `−103.5 … −133.5` | **帧墙厅**：两侧挂满"看过的帧"，一道扫描线扫过去 | 线段 + 同一份 SDF |
| `−132.2` | **末端墙**：落版（SDF 里材质 5 的发光板，片名浮在它上面） | SDF + 2D 文字 |

## 3. 三条"连续性"是怎么做出来的

1. **一台摄影机**：`_world.js` 的 `camAt(t)` 只吃整片时间。位置不是关键帧插出来的，而是
   **速度剖面的积分**（`V_KEYS` → `speedAt()` → `zAt()`）—— 于是切点上位置与速度**双双连续**。
   （第一版用位置关键帧 + 缓动，每个内部关键点都被缓动"掐"到近停：实测 36.0s 处两侧速度比 153×。）
2. **一个母题**：`motifAt(t)` 那支光标。段 1 是编辑器里那根竖线 → 段 2-4 是镜头前面拖着尾迹的光点
   → 段 5 是扫描线 → 段 6 落到片名后面变成那根光标。六个分支的接缝都按"下一段的起点"
   校准过（探针逐帧量：最大单步位移 0.043 世界单位）。
3. **一套调色**：`grade(t)` 是整片唯一的一套 post 参数（底子 + 穿门那一下的亮 + 三个切点上的一口气），
   相邻两段在边界上算出来的是**同一个值**。零 overlap 的硬切因此连一帧的曝光差都没有。

> 机械验收：`node out/_probe/continuity.mjs`（或 `node out/_probe/preflight.mjs` 一起跑）——
> 五个边界的位置/朝向/滚转/速度比/调色差、母题逐帧位移、摄影机始终在世界腔体内，全部有判据。

### 3.1 手持抖动：必须是"呼吸"，不是"地震"（用户反馈后改的）

第一版的 `postAt()` 照抄了 `tasks/pdoom-lab` 的 `camPost()`：`(hash2(f.idx, 11) - 0.5) * 2 * amp`
—— 那是**逐帧白噪声**，60fps 下不是手持，是高频振动；而且幅度只升不降（26→36s 升到 5px 后
**一直保持**），偏偏 42–48s 摄影机已经停住，画面上只剩这个抖动 → 用户的原话是
「最后那里都快和地震一样了」。

成片实测（`node out/_probe/jitter.mjs out/promo/promo.mp4 46.5 8`，相邻帧互相关）：

| 量 | 修之前 | 修之后 |
|---|---|---|
| 成片逐帧整体位移（t≈46.5s） | ±2–8 px，RMS 3.64 px | **±1 px，RMS 0.27 px** |
| 成片相邻两帧位移之差 | 最大 13 px | **最大 1 px** |
| 设计值 `\|shake\|` 最大 | 4.99 px | 2.44 px |
| 设计值**逐帧变化量** | 最大 10.19 px / RMS 3.03 px | **最大 0.14 px / RMS 0.04 px** |

改法：两段**低频值噪声**（`noise1`，0.85Hz + 2.7Hz）当手持，幅度 1.1px（安静段）→
2.4px（俯冲）→ 落版衰减到 0.25 倍。用 `t` 而不是 `f.idx`：平滑函数在一帧的 8 个子帧之间
只差约 0.02px，不会双重曝光（那才是白噪声的问题），又会像真实抖动那样被运动模糊带一点。

引擎侧的证据与建议（仓库里两条并存的写法、`handheld()` 的默认行为等）写在 `docs/IMPROVEMENTS-3.md`。

## 5. 音乐

`scripts/make-promo-audio.mjs` 生成（纯合成、确定性、无版权问题）：48.000s / 120bpm / 24 小节，
peak −1.0 dBFS，每拍都有 kick（96/96）。编排与切点对齐：

| 时刻 | 画面 | 音乐 |
|---|---|---|
| 0.0 | 光标打字 | 只有 kick + 极轻 pad（最轻的一段） |
| **6.0** | 爆冲进走廊 | hat + bass 进 + boom + 吊镲 |
| **16.0** | 穿门 → 大厅 | 全奏 + sub boom |
| **26.0** | 坠入晶格（俯冲） | 十六分 hat + 高音 arp + 第二记 boom（全片最响） |
| **36.0** | 帧墙 | 抽掉 hat 与 arp（掉 3.4 dB） |
| **42.0** | 落版 | 大重击 + 主和弦 + 长吊镲 → 最后 2 秒淡出到静音 |

分析结果：`audio/bed.analysis.json`（bpm 120 / 96 拍 / 101 kick）。
